AI & Prompt Engineering Academic Project

AI Review Framework & Prompt Architecture

Demonstrating the principles of structured prompt engineering for career readiness evaluation. This section illustrates how modern Large Language Models (LLMs) can be guided with precision constraints, preventing hallucinations and enforcing deterministic evaluation criteria.

The 5 Pillars of Technical Prompt Engineering

Pillar 1
ROLE
Assigns domain persona & expertise (e.g. Senior Technical Recruiter) to establish evaluation standards and tone.
Pillar 2
CONTEXT
Frames the candidate level (college fresher vs senior) so recommendations remain realistic and feasible.
Pillar 3
TASK
Defines precise objectives: skill extraction, gap identification, section audit, and prioritization.
Pillar 4
OUTPUT FORMAT
Enforces structured numbering, JSON, or markdown headers for clean, programmatic readability.
Pillar 5
CONSTRAINTS
Negative guards: prevents inventing skills, hallucinating experience, or vague motivational fluff.
Structured Resume Review Prompt (Production Standard)
ROLE: Act as a professional resume reviewer and entry-level technical recruiter. CONTEXT: Analyze a college student's resume for a specific internship/job role. The candidate may have limited professional experience. TASK: Evaluate the resume against the job description, identify strengths, missing skills, weak sections and improvements. OUTPUT FORMAT: 1. Overall assessment 2. Relevant skills 3. Missing skills 4. Resume weaknesses 5. Improvement suggestions 6. Learning priorities CONSTRAINTS: - Do not invent experience, achievements or skills. - Make realistic recommendations for students. - Clearly differentiate possessed skills from skills that need learning. - Use clear, actionable language.

Interactive Prompt Evolution: From Basic to Engineered

Compare how progressively adding architectural constraints transforms generic LLM output into an objective, recruiter-grade analysis.

"Review this resume and tell me if it's good for a software job."
Critical Weaknesses & Hallucination Risks:
  • Zero role framing: LLM often acts as a polite cheerleader rather than a recruiter.
  • No job description context: Cannot calculate match percentage or identify specific missing skills.
  • Unpredictable output format: Returns unstructured paragraphs that cannot be compared across candidates.
Prompt Engineering Diagnosis:

Lacks Role, Context, Constraints, and Target benchmark. Susceptible to sycophancy (telling the user what they want to hear).

"Act as a recruiter. Review this student resume against this job description. List matching skills, missing skills, and give tips to improve."
Key Improvements:
  • Defines persona (Recruiter) and dual inputs (Resume + Job Description).
  • Directs attention toward matching vs missing skills.
Remaining Vulnerabilities:

No negative constraints. The model might invent work experience, recommend senior-level architectures unsuitable for students, or hallucinate skills.

"ROLE: Technical Recruiter for freshers | CONTEXT: College student entry-level role | TASK: Cross-reference resume skills vs JD requirements | OUTPUT: 6-part numbered schema | CONSTRAINTS: Negative boundary preventing skill fabrication."
Production Advantages:
  • Deterministic structure: Every candidate receives uniform evaluation headers.
  • Zero skill fabrication: Explicit negative constraint stops hallucinated competencies.
  • Targeted recommendations: Focuses on realistic student artifacts (GitHub, mini-projects, coursework).
Viva Presentation Highlight:

Demonstrates how Prompt Architecture transforms generative LLMs into reliable, reproducible evaluation tools.

Viva & Project Defense Discussion Points

When presenting this major project to internal/external examiners, emphasize these core engineering principles:

  • Client-Side Rule-Based Engine vs Generative AI: Explain that this web application uses high-precision regex boundary matching (`\b[Cc]\b` for C, lookahead for Java vs JavaScript) to guarantee 100% deterministic, zero-hallucination skill extraction without cloud API latency or ongoing costs.
  • Prompt Architecture as a Software Layer: Explain how the Role-Context-Task-Output-Constraint (RCTOC) framework enforces deterministic JSON/Markdown schemas when interfacing with real-world LLMs.
  • Ethical ATS Scoring Disclaimer: Commercial ATS systems do not simply compute a single percentage; they parse layout trees and keyword frequencies. CareerFit transparently decomposes scoring into Skill Match (50%), Completeness (20%), Keyword Alignment (20%), and Quality (10%) for student educational feedback.
